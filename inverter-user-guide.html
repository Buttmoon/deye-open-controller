Руководство пользователя

Это автономное руководство по приложению Deye Open Controller (планировщик и управление инверторами). Оно открывается в браузере без сервера и описывает реальные экраны, кнопки и последствия действий.

Важно о безопасности. Просмотр значений и правка настроек приложения не меняют инвертор. Создание расписания тоже не пишет регистры сразу — запись выполняет планировщик в назначенное время. Прямая запись Modbus (тестирование регистров, ручная запись, ограничение мощности) требует явного подтверждения и оставляет след в истории.

1. Введение

Приложение управляет несколькими гибридными инверторами Deye: расписания Time Of Use, мониторинг, история операций, шаблоны и безопасная работа с регистрами Modbus.

Для оператора

Упрощённый режим расписания, состояние инверторов, история заданий — без знания адресов регистров.

Для администратора

Расширенный редактор, профили регистров, тестирование регистров, API /health и /api/modbus/*.

2. Первый запуск

Запустите исполняемый файлОдин бинарник содержит интерфейс и профили по умолчанию. Каталог templates/ отдельно распространять не нужно.
При первом старте создаются каталоги данныхdata/ (БД, логи, резервные копии) и при необходимости файлы профилей. Пользовательские правки профилей не перезаписываются.
Откройте веб-интерфейсОбычно адрес вида http://<хост>:8081 (или значение INVERTER_SCHEDULE_ADDR).
Проверьте часовой поясВ Настройки → Общие. От него зависят выполнение расписания и метки времени в журналах.
Переменные окружения

  • INVERTER_SCHEDULE_WORKDIR — рабочий каталог для данных и профилей

4. Добавление инвертора

Откройте главнуюРаздел «Добавить инвертор» или якорь меню.
Укажите имя, IP и портТипичный порт Modbus TCP — 502 или производительский (часто 8899).
Выберите модельОт модели зависит JSON-профиль регистров. Неправильная модель → неверные адреса и шкалы.
СохранитеИнвертор появится в списке. Расписание пока пустое или шаблонное.
Выбор модели не пишет в устройство. Запись начнётся только при выполнении расписания или ручной операции.

5. Проверка связи

Интеграционный health-эндпоинт приложения:

GET /health → {"ok":true,"message":"deye-open-controller"}

Для проверки самого инвертора:

  • Страница Состояние инверторов → «Обновить» — живое чтение поддерживаемых регистров.
  • Страница Тестирование регистров → чтение известного адреса (например 146).
  • API POST /api/modbus/read — блочное чтение holding-регистров.
Одиночный сбой не сразу помечает инвертор «не в сети»: нужен настраиваемый порог подряд идущих ошибок.

6. Состояние инвертора

Страница Состояние инверторов показывает только параметры, которые есть в профиле модели: онлайн/офлайн, SOC, мощности сети/нагрузки/PV, режим, предупреждения, активность планировщика.

кэш

При открытии страницы инверторы не опрашиваются. Видны сохранённые значения с меткой времени.

живые

Кнопка «Обновить» или фоновый опрос (если включён в настройках) получают свежие данные.

Серийный номер и версия ПО показываются только если соответствующие коды есть в профиле. Для многих карт они не заданы — это не ошибка приложения.

7. Создание расписаний

Два совместимых режима поверх одной модели данных (почасовые слоты + маска Use Timer / регистр 146):

Упрощённый режим
правила → часы
⇄
Расширенный режим
каждый час вручную
→
Планировщик
запись в TOU
Сохранение расписания в приложении не равно записи в инвертор. Планировщик применяет значения в нужный час, с отключением Use Timer на время записи и контрольным чтением.

8. Упрощённый режим

Меню: Расписание → Упрощённый режим (/schedules/simple).

Сценарий: расписание на будни

Выберите инверторОтметьте нужные устройства чекбоксами. Можно применить одно правило сразу к нескольким.
Откройте упрощённый режимУбедитесь, что функция включена в Настройки → Функции.
Выберите Пн–ПтВ правиле отметьте дни недели, когда действует интервал.
Задайте часыНапример 08:00–18:00 — дневной режим, 18:00–08:00 — ночной. Можно добавить образец «Продажа вечером».
Укажите мощность и SOCПоля мощности и ёмкости батареи — в единицах интерфейса расписания. Лимит экспорта — по необходимости.
ПредпросмотрКнопка предпросмотра показывает развёрнутые часы и пересечения правил (действует правило ниже по списку).
СохранитеРежим «Дополнить» сохраняет часы вне правил; «Заменить» выключает их. Параметры, которые упрощённый режим не показывает, не удаляются молча — при риске есть предупреждение.
Проверьте историюОткройте История заданий и изменений: сохранение и последующие записи регистров появятся с статусами.

9. Расширенный режим

Страница Расширенный режим (/schedules) сохраняет полный редактор: каждый час, режимы заряда, лимиты, маска Use Timer, приоритет нагрузки, импорт/экспорт.

Регистр 146 (Use Timer)

Это битмаска, а не логическое 0/1:

  • бит 0 — таймер включён;
  • биты 1–7 — Пн…Вс;
  • бит 8 и выше — сохраняются при masked-записи, не считаются частью недельной маски 0–255.

Старое ограничение allowed_values: [0,1] снято: значения вроде 255 для всех дней допустимы.

10. Повторяющиеся задания

  • В упрощённом режиме — опция «Повторять ежемесячно»: правила пересчитываются в начале месяца, если расписание не правили вручную в расширенном режиме.
  • Шаблоны и «Добавить по образцу» ускоряют типовые сценарии (ночной заряд, вечерняя продажа, выходные).
  • Копирование расписания и дублирование шаблонов доступны через API/кнопки на страницах шаблонов.
Движок выполнения по-прежнему опирается на почасовую модель. Упрощённый редактор только генерирует её.

11. Импорт Excel-шаблонов

Страница Импорт XLSX. Legacy-колонки не переименовываются:

Day, Hour/Time, SellModeKW, SellModeBattCapacity, ChargeMode, GridExportLimit, GridChargeEnabled, LoadLimitMode, UseTimer*, PriorityLoad.

Скачайте пример или используйте свой файлФайл вида «2409_ТЕСТ_ТУРА» с почасовыми строками поддерживается.
Загрузите и просмотритеПеред применением доступен предпросмотр и понятные ошибки валидации.
Примените к инверторамЧерез шаблоны или назначение расписания.
Если колонки Use Timer пустые, а строки заполнены, импорт включает маску 255 (все дни), чтобы TOU оставался исполняемым.

12. Экспорт расписаний

Из расширенного режима / списка инверторов — экспорт в XLSX с тем же набором колонок. Экспортируются только включённые часы, чтобы повторный импорт не «оживлял» пустые дни.

Упрощённые шаблоны дополнительно экспортируются в JSON.

13. Определения регистров

Каждая модель ссылается на JSON-профиль в device_parameters/. В карточке регистра отображаются: адрес, код, описание, тип, ширина, знаковость, доступ, диапазоны raw/engineering, масштаб, единицы, enum/биты, совместимость, источник и статус достоверности.

Если в профиле только 0 и 1 — это не доказательство, что регистр булевый. Для битовых полей смотрите write_mode: masked_bits и описания битов.

Установка непроверенного на оборудовании профиля после структурной проверки не блокируется предупреждением. Значок «не проверен» — информационный. Опасная запись по-прежнему требует отдельного подтверждения модели.

14. Безопасное тестирование регистров

Страница Тестирование регистров.

Чтение

Raw, hex, bin, расшифровка, биты, время чтения, ошибки связи.

Запись

Сначала dry-run предпросмотр. Реальная запись — только с подтверждением, затем read-back и запись в историю.

  • Редактор битовых масок меняет только известные биты и сохраняет остальные (RMW).
  • Автоперебор 0…255 не выполняется.
  • Наблюдения и правки метаданных профиля — с резервной копией и откатом.
  • Запись со страницы включается в Настройки → Функции.

15. История заданий и изменений

Страница История заданий и изменений хранит операции в SQLite и переживает перезапуск.

Фильтры: дата, инвертор, тип, статус, адрес регистра, поиск. Экспорт CSV/XLSX. Раскрытие показывает попытки повтора и дочерние записи регистров.

СтатусСмысл
ЗапланированоОперация принята, ещё не выполняется
ВыполняетсяИдёт запись/опрос
ПримененоКоманда отправлена
Подтверждено чтениемRead-back совпал с ожиданием

Статус «Подтверждено чтением» выставляется только после успешного контрольного чтения. Запись без read-back так не называется.

16. Контроль выполнения расписаний

  • Журнал задач — запуски планировщика.
  • История — детальные записи регистров внутри запуска.
  • Лента/календарь на страницах расписания — визуализация слотов и конфликтов.
  • Кнопки «Выполнить сейчас» / «Перезапустить предыдущее» — осознанный ручной запуск.

17. Настройки

Единый хаб /settings с вкладками:

  1. Общие — часовой пояс, оформление.
  2. Инверторы — опрос состояния, каталог моделей, время на устройстве.
  3. Регистры — профили, установка/экспорт, индикаторы проверки.
  4. Расписания — поведение редактора по умолчанию.
  5. Функции — ограничение мощности, упрощённый режим, запись с тестовой страницы.
  6. Уведомления — переходы к SMTP/Telegram/рассылке.
  7. Система — версия сборки, резервные копии, диагностика, очистка.

18. Ограничение мощности (Grid Peak Shaving)

Функция по умолчанию выключена для новых установок (feature.grid_peak_shaving=0).

Когда выключена:

  • карточка скрыта на главной;
  • запись регистров 178/191 из UI/теста блокируется;
  • сохранённые в БД значения не удаляются;
  • физический режим на инверторе не выключается автоматически.

Когда включена администратором:

  • регистр 178 — RMW только bits 4–5;
  • регистр 191 — лимит мощности с шагом и пределами модели;
  • обязательны подтверждение и read-back, всё пишется в историю.

19. Резервные копии и восстановление

  • data/app.db — расписания, инверторы, история, настройки KV.
  • data/backups/ — копии профилей при обновлении встроенных defaults.
  • Раздел Система — создание резервной копии через API/UI.
  • Кастомные JSON профилей не затираются при обновлении бинарника.
Секреты SMTP/токенов хранятся в БД. Ограничьте доступ к data/.

22. Часто задаваемые вопросы

Нужен ли каталог templates рядом с бинарником?

Нет. HTML/CSS/JS и defaults встроены через go:embed. Нужен только доступный каталог данных.

Почему упрощённый режим «не видит» часть полей?

Они сохранены в полном JSON расписания. Переключение режимов не должно их молча уничтожать; при риске потери показывается предупреждение.

Можно ли работать без записи в инвертор?

Да: просмотр состояния (кэш), правка расписаний, шаблоны, история. Запись — только планировщик или явные действия с подтверждением.

Где API для внешней системы?

GET /health, POST /api/modbus/read (JSON), POST /api/modbus/write (form). Auth — как настроено у остальных API.

Как собрать Linux и Windows?

./build.sh release создаёт dist/inverter-schedule-linux-amd64 и dist/inverter-schedule-windows-amd64.exe.
